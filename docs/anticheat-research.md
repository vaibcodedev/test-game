# Античит: исследование (Phaser 3.90 + Colyseus 0.16 + SQLite)

Дата: 2026-10. Наши версии: `@colyseus/core` ^0.16.26, `@colyseus/schema` ^3.0.76, `@colyseus/ws-transport` ^0.16.5, БД `node:sqlite`.

## Текущее состояние (server/src/rooms/WorldRoom.ts, common.ts)

- Общий обработчик есть: все сообщения идут через `makeOn()` → `floodCheck()` (окна по `windowMs`, отдельные счётчики «движение» и «прочее», серия превышений → кик без переподключения, запись в лог). `onMessage("*")` гасит неизвестные типы с тем же лимитом.
- Базовая проверка: `msg` должен быть объектом; числа режутся `num(v, min, max)` прямо в обработчиках. Единой схемы на тип сообщения нет.
- Движение уже авторитетно: клиент шлёт направление `mx,my ∈ [-1,1]`, позицию считает сервер (спидхак и телепорт по координатам невозможны).
- `onAuth`: сессионный токен HTTP API, владение героем, бан, один герой на аккаунт, вытеснение старой вкладки. Версия клиента не проверяется.
- Транзакции SQLite есть в db.ts, торговле, банке, сумках, арене.
- `maxClients = 200`, `allowReconnection` с таймаутом, транспорт `ws` без явных `maxPayload`/`verifyClient`.

## Что даёт Colyseus

| Механизм | Версия | Что делает | Замечание для нас |
|---|---|---|---|
| `onAuth(client, options, context)` | 0.16 | Проверка до входа в комнату, результат в `client.auth`; `context` — заголовки и IP | Используем. Можно добавить версию клиента и лимит по IP |
| `onMessage(type, fn)` + `"*"` | 0.16 | Обработчики по типу; неизвестный тип без `"*"` — дисконнект 4002 | Есть общий `makeOn` |
| `validate(zodSchema, handler)` | только новые доки (0.17) | Встроенная проверка сообщения Zod, при ошибке — дисконнект 4002 | В 0.16 нет; делаем сами |
| `maxMessagesPerSecond` | 0.17 | Лимит сообщений клиента в секунду, превышение — дисконнект. По умолчанию `Infinity` | В 0.16 нет; наш `floodCheck` гибче (по типам) |
| `WebSocketTransport.maxPayload` | 0.16 | Предел размера входящего кадра, по умолчанию 4096 байт; больше — закрытие | Задать явно (≈4–16 КБ) |
| `pingInterval` / `pingMaxRetries` | 0.16 | Отсечение мёртвых соединений (3000 мс / 2) | Ок по умолчанию |
| `verifyClient(info, next)` | 0.16 (ws) | Проверка до рукопожатия: `Origin`, IP | Отсекать чужие `Origin`, лимит соединений с IP |
| `beforeUpgrade` | новые доки | Асинхронная проверка до апгрейда (token, headers, ip) | После перехода на 0.17 |
| `StateView` + `@view()` | 0.16 (замена `@filter`) | Каждому клиенту — только видимая ему часть состояния | У нас свой `Visibility`. Главная защита от wallhack/радара: не слать лишнего |
| `allowReconnection(client, sec)` | 0.16 | Удержание места; `reconnectionToken` новый при каждом подключении | Токен — секрет сессии, не логировать |
| `seatReservationTimeout` | 0.16 | 15 с на вход после резервации места | Ок |
| Шифрование | — | Своего нет. Только TLS (`wss://`) через reverse proxy (nginx/Caddy) | Обязателен `wss` в проде |
| `uWebSocketsTransport` | 0.16 | Быстрее `ws`, опция `maxPayloadLength` (4096) | Античиту ничего не даёт; переходить только ради нагрузки |

Известные уязвимости: в GitHub Security Advisories у `colyseus/colyseus` опубликованных нет (на 2026-10), CVE на `@colyseus/schema` не найдено. Риски — собственная логика и зависимости (`ws`, `express`): держать `npm audit` чистым.

## Лучшие практики

| Угроза | Защита | Где |
|---|---|---|
| Подмена позиции, спидхак, телепорт | Клиент шлёт только намерение (направление, цель, id умения); позицию считает сервер. Если когда-то принимать координаты — проверять `dist ≤ speed·dt·1.2` и проходимость, иначе откат | Сервер, симуляция |
| Неверные/огромные поля сообщения, `NaN`, прототип-загрязнение | Схема на каждый тип (typebox/zod), `additionalProperties:false`, длины строк и массивов, целые id; отказ → счётчик нарушений | Сервер, общий `on()` |
| Флуд, спам умениями, DoS | Лимит по типу сообщения (token bucket), `maxPayload`, лимит соединений с IP | Сервер, транспорт |
| Обход кулдаунов, атака дальше дистанции | Кулдаун, ресурс, дистанция, линия видимости, состояние (жив, не в стане) — только на сервере, от времени сервера | Сервер, боёвка |
| Завышенный урон | Урон считает сервер из своих статов; sanity-check: урон за удар ≤ теоретического максимума, DPS за окно ≤ предела → лог | Сервер |
| Дюп предметов и золота | Одна транзакция SQLite на обмен/покупку/почту (`BEGIN IMMEDIATE`…`COMMIT`), проверка «было → стало», уникальный id предмета, идемпотентные операции, блок инвентаря на время обмена, сохранение перед выходом | Сервер, БД |
| Двойной клик / повтор сообщения (replay) | Порядковый номер или id запроса у экономических действий, сервер помнит последние; WS внутри TLS сам по себе не даёт стороннего replay | Сервер |
| Кража сессии | Короткоживущие токены, `wss`, не класть токен в URL/логи, привязка сессии к аккаунту, выход — отзыв | HTTP API, onAuth |
| Wallhack, радар, «видеть лут в тумане» | Не отправлять то, что герой не видит (фильтр видимости), скрытые статы и дроп не слать заранее | Сервер, `Visibility`/StateView |
| Старый или изменённый клиент | Версия сборки в `onAuth`, отказ старым («обновите страницу»); хеш сборки — только как сигнал, не защита | onAuth + сборка |
| Боты и макросы | Серверная статистика: идеальная регулярность интервалов (низкий разброс), 24/7 онлайн, повтор маршрутов, реакция быстрее человека; капча/вопрос при подозрении | Сервер, аналитика |
| Мультиаккаунт, фарм-фермы | Лимит героев онлайн на IP/аккаунт, связка аккаунтов по IP/отпечатку, задержка торговли новым аккаунтам | HTTP API, onAuth |
| Нарушитель не знает, что пойман | Журнал подозрительного (таблица `suspicion`: кто, что, значение, время), баллы с затуханием; теневой бан (матчмейкинг с такими же, без лута) и волны банов, а не мгновенный бан | Сервер, БД, админка |

Про клиент в браузере (Phaser):
- Бесполезно как защита: любые проверки в JS клиента, «защищённые» переменные, детект DevTools, клиентский античит — всё снимается за минуты (локальный прокси, переопределение `WebSocket`, Tampermonkey).
- Обфускация (javascript-obfuscator, terser с mangle): только повышает порог для новичков и мешает быстро написать бота по исходнику; цена — размер и скорость. Достаточно минификации Vite + отключённых source maps в проде.
- Полезно: проверка версии клиента (отбрасывать старые после обновления протокола), `Origin` в `verifyClient`, CSP и SRI для своих скриптов (защита игроков от чужих скриптов, а не сервера от игроков), ничего секретного в бандле.

## Готовые библиотеки

| Библиотека | Для чего | Подходит |
|---|---|---|
| [rate-limiter-flexible](https://github.com/animir/node-rate-limiter-flexible) | Token bucket в памяти/Redis; лимит соединений с IP, входов, HTTP API | Да: `RateLimiterMemory` для IP и логина; per-message — наш `floodCheck` уже достаточен |
| [@sinclair/typebox](https://github.com/sinclairzx81/typebox) + `TypeCompiler` | Схема = TS-тип, компилируемая проверка, очень быстрая | Лучший выбор для горячих сообщений (`input`, `cast`) |
| [zod](https://zod.dev) | Удобные схемы, понятные ошибки; медленнее typebox | Для редких сообщений и HTTP API; совместим с `validate()` Colyseus 0.17 |
| [express-rate-limit](https://github.com/express-rate-limit/express-rate-limit) | Лимит HTTP-маршрутов (вход, регистрация, matchmake) | Да, для `/api/*` и `/matchmake` |
| helmet | Заголовки безопасности (CSP и др.) для express | Да, дёшево |
| javascript-obfuscator | Обфускация клиента | Низкий приоритет |

## Рекомендация для нас (по приоритету)

| # | Мера | Зачем | Сложность |
|---|---|---|---|
| 1 | Явно задать `maxPayload` (8–16 КБ) и `verifyClient` с проверкой `Origin` в `WebSocketTransport` | Отсечь огромные кадры и чужие сайты | Низкая (10 строк, index.ts) |
| 2 | Версия клиента: `BUILD_ID` из Vite в опции join, сверка в `onAuth`, отказ 426 «обновите страницу» | Не принимать старые клиенты с другим протоколом | Низкая |
| 3 | Схемы сообщений: таблица `type → typebox-схема` в `makeOn`, отказ = балл нарушения, без исключений в обработчиках | Убрать ручные `num()`, закрыть неожиданные поля и типы | Средняя (много типов, делать по группам) |
| 4 | Аудит экономики: каждая операция с золотом/предметами — одна транзакция `BEGIN IMMEDIATE`, сверка суммы до/после, id запроса против двойной отправки | Защита от дюпа (самая дорогая угроза MMO) | Средняя, core-engineer |
| 5 | Журнал подозрительного: таблица `suspicion` + функция `flag(p, kind, value)`; вызывать из `floodCheck`, отказов схемы, sanity-check урона/дохода в час, кликов «сквозь стену» | Видеть читеров до жалоб, основа банов | Средняя |
| 6 | Лимиты по IP: `rate-limiter-flexible` на вход/регистрацию и число соединений с IP (например, 5) в `onAuth` | Брутфорс, фермы ботов | Низкая |
| 7 | Проверка кулдаунов, дистанции, LoS всех умений и взаимодействий с NPC/сундуками на сервере (ревизия, что ничего не доверяется клиенту) | Обход кулдаунов и «дальний» лут | Средняя (ревизия) |
| 8 | Детект ботов: разброс интервалов ввода, часы онлайн подряд, повтор маршрута → баллы в журнал; админ-просмотр | Боты фарма | Средняя–высокая, после релиза |
| 9 | Теневой бан и волны банов (флаг в БД: без дропа/торговли, свой матчмейкинг) | Читер не понимает, что пойман | Средняя |
| 10 | `wss` за nginx/Caddy, helmet + CSP, `npm audit` в CI | Базовая гигиена | Низкая |
| 11 | Обфускация клиента | Слабый эффект | Не делать сейчас |
| 12 | Переход на Colyseus 0.17 (`validate`, `maxMessagesPerSecond`, `onDrop/onReconnect`) | Встроенные средства, но наш код уже их покрывает | Высокая (ломающие изменения `onLeave`, `Room`) — позже |
