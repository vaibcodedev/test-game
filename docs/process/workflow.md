# Работа с агентами, git и версия игры

**Когда читать:** координатору — в начале сессии и перед запуском агентов; агентам — перед прогонами с сервером и перед правкой общих файлов.
**Главное:** агенты не трогают git (коммитит координатор); прогоны с сервером — строго по одному под замком `tools/out/scenario.lock*`; отчёт агента до 5 строк; читать только указанные файлы; при каждом обновлении поднимать версию в `data/version.json`.

## 1. Агенты и модели

| Агент | Модель | Что делает | Гайды |
|---|---|---|---|
| core-engineer | Opus | только задачи с пометкой core-engineer и баги после 2 неудач; сервер, база, экономика, античит, боты | [architecture](../systems/architecture.md), [tests](tests.md) |
| feature-dev | Sonnet | фичи, умения классов, поведение монстров, интерфейс, арт через генератор | по теме из таблицы в CLAUDE.md |
| content-writer | Haiku | тексты, лор, баланс цифр, предметы и мобы по шаблону — только `/data` | [lore](../content/lore.md), [balance](../plan/balance.md) |
| tester | Haiku | проверка в конце этапа: запуск, тесты, логи; код не исправляет | [tests](tests.md) |

## 2. Порядок

1. Взять следующую задачу из [docs/plan/plan.md](../plan/plan.md).
2. Передать нужному агенту короткое задание, список нужных файлов и гайды по теме.
3. Мелкие задачи (интерфейс, тексты) координатор делает сам.
4. Не работает — вернуть тому же агенту; после 2 неудач — core-engineer.
5. Проверка (`npm run typecheck`, нужные тесты — [tests.md](tests.md)), git commit, отметка в плане, подъём версии.
6. Этап закончен — tester, затем перенос следующего этапа из [backlog.md](../plan/backlog.md) в plan.md.
7. После 1 крупной или 3 мелких задач — остановиться и написать «Начни новую сессию».

## 3. Исследование перед проектированием (правило владельца)

Перед проектированием любой системы, интерфейса, арта или эффекта — посмотреть, как это сделано в топовых MMORPG того же жанра: WoW, Lineage 2, Lost Ark, Black Desert, Aion, Guild Wars 2, Albion, для 2D-мира — Warspear Online. Искать в интернете (WebSearch), сравнивать 2–4 игры, брать лучшие практики; стиль оставлять свой, ассеты не копировать. Варианты владельцу — с пометкой, откуда идея.

## 4. Параллельность и замки

- Число параллельных агентов — по последнему слову владельца (2–6). Параллельно — только задачи с непересекающимися файлами.
- Прогоны с сервером, Vite и Chrome (скриншоты, сценарии) — **строго по одному**, под замком `tools/out/scenario.lock` (у отдельных сценариев свой номер, например `scenario.lock3` у снимков героя Б). Перед запуском проверить замок; занят — ждать, не удалять чужой.
- Сервер разработки занимает порт 5173; тестовый Vite — свой порт, его нужно разрешить в `data/anticheat.json` → origins.
- `npm run assets` — долгая полная пересборка; без нужды не запускать. Атлас — отдельно `tools/gen/atlas.ts`; объекты — своими установщиками.

## 5. Git

- Агентам нельзя: git add, commit, stash, checkout -- <файл>, reset, restore — рабочее дерево и индекс общие. Старую версию смотреть через `git show HEAD:<файл>` или `git worktree`.
- Коммитит координатор, только своё; ветка `main`. Сообщение — кратко по-русски.
- Репозиторий приватный: в истории паки с запретом раздачи — публичным делать нельзя.

## 6. Версия игры

- `data/version.json`: `stage` (показывается игроку, сейчас «Альфа») и `version`. Координатор поднимает patch **при каждом обновлении**, minor — на крупных вехах.
- Позже — журнал изменений (docs/changelog), не сделан.

## 7. Общение с владельцем

- Все ответы и сводки — по-русски.
- Выбор и материалы (референсы боссов, материал сета и т. п.) — спрашивать через опросник (AskUserQuestion) заранее.
- Решения владельца записывать в профильный гайд с датой, дословно по смыслу.
- Перед показом арта — [quality-bar.md](../art/quality-bar.md) §5. Скриншоты удалять после успешной проверки; показанные владельцу — после его ответа.

## 8. Экономия

- Агенты читают только указанные файлы и гайды, весь проект не читают.
- Отчёт агента — до 5 строк.
- Новый контент — в `/data`, не в коде.
- Документы не плодить: новое правило — в существующий гайд по теме; история — в git, а не в доках.

- Зависший замок `tools/out/scenario.lock*` (процесс с PID из файла не существует) можно удалять без вопроса владельцу — сначала проверить PID (владелец, 2026-10-31). Живой чужой замок не трогать.
- Запуск игры: `npm run dev` — сначала пересобирает все ассеты (несколько минут); `npm run dev:fast` — сразу, на уже собранных (2026-10-31).
